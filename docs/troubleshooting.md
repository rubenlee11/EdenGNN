# Troubleshooting

[User guide](index.md)

## Prediction runs out of GPU memory

Decrease `model.chunk_size_predict`. For training, decrease `model.chunk_size_train` instead. Keep `data.batch_size: 1`. The reference chunk size of 20,000,000 for an 80 GB GPU is a starting point; actual memory use depends on the structure and model.

Do not reduce channels or change architecture when using an existing checkpoint. For a new training run, model size and the maximum structure-grid size can also be reduced if needed.

## CPU execution fails with zero GPUs

Set `run.device: cpu` and retain `run.num_gpus: 1`. The current training/inference path does not accept `num_gpus: 0`.

## VASP prediction cannot find a label or prior

VASP filelists must contain SAD calculation directories. Each requires the SAD CHGCAR from an actual VASP run. For training, `data.vasp.dir` points to the SCF parent and its child names must match the SAD directory names.

A CIF path, an SCF directory substituted for SAD, or a path to the CHGCAR file itself does not match this workflow.

## VASP grids or augmentation settings disagree

Keep the same generated primitive POSCAR, atom order, PAW versions, `ENCUT`, `PREC`, FFT grids, and `LMAXMIX` across the workflow. Set `data.vasp.lmix_max` to match `LMAXMIX`. Do not combine predictions from unrelated structures or inconsistent model configurations.

For separate predictions, concatenate the pseudo-density file first and the augmentation file second. A task-2 checkpoint already outputs a combined file and must not be concatenated with itself.

## Fixed-density VASP produces no useful bands

Change SAD's `NELM=0` to a positive value, such as `100`, and use `ICHARG=11` for the final calculations. Use `KPOINTS_BAND` for the band path and `KPOINTS_SCF` for the uniform DOS branch.

## ABACUS cannot read the predicted cube

Use the difference-density-patched ABACUS build. Generated predictions place the difference density at `OUT.EDENGNN/SPIN1_CHG.cube`, with `init_chg drho`. This cube is not a total density. For total-density DFT restart files use `init_chg file` instead.

For training, use `chgdelta.cube` generated by `out_chg 3`, with `data.abacus.prefix` matching the actual training suffix.

## ABACUS input generation fails

The template passed to the input generator or prediction configuration is a parameter-only file without `INPUT_PARAMETERS`. It must include the intended `ecutwfc`. Generated calculation INPUT files include the header and can be run directly.

Check that the configured `pp.json` points to existing, matching pseudopotential and orbital files on the execution machine.

## No best checkpoint was saved

Allow validation and at least two epochs for the best-checkpoint path in a short run. A one-epoch demonstration may only save a regular checkpoint under `checkpoints/`. Select a checkpoint that actually exists and retain its complete training configuration.

## DFT comparison cannot find outputs

Both backend statistics scripts expect `nscf/`, `band/`, `scf/`, and `band_scf/` under each listed structure directory, unless a separate target root is supplied. Do not give the SAD parent or just a band directory as the plotting/statistics filelist entry.

ABACUS comparison also requires `out_band 1` for the uniform-mesh calculations, plus matching `--prefix` and `--prefix-tar`. Preserve the actual `running_scf.log` of the reference SCF; do not rename an NSCF log to make it look like SCF.

## PyATB preparation or comparison fails

Check that H, S, and rR exist and that the matching ABACUS log contains `EFERMI`. The helper reads the actual calculation STRU. For comparisons, match filelist order and use identical energy grids, integration meshes, and broadening for both sides.

Increase optical integration density when spectral convergence requires it; reducing the photon-energy step alone does not refine Brillouin-zone sampling.

## A job launcher exits without running DFT

Configure `~/.edengnn/scripts/<backend>/submit.sh` with the actual executable and MPI command. The repository launchers are placeholders. Execute synchronous local launchers with Bash; submit scheduler jobs with `sbatch`, `qsub`, or the site-specific scheduler command. A file containing `#SBATCH` lines is not submitted by running `bash`.

Inspect the stage's prediction log, `info.log`, DFT output, or scheduler log to identify the failing command. Keep `set -e` and success dependencies so failed stages do not trigger downstream calculations.
